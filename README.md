# 工作台（DSH Workbench）

把各家 AI 产品的「工作台」搬进 DSH 输入框：一个工作台 = 一段场景系统提示词 + 一组配套技能。选定某个工作台，它的规则就注入**当前会话**的系统提示。

**开箱自带**：一个 **Godot 游戏开发工作台**（58 个技能，8 组，含本机环境事实与工程纪律）。**可选扩展**：从任意 AI 产品抓取的工作台，按同一份数据格式放进 `data/` 即可并列出现。

**设计上不绑定任何平台**：工作台数据是一层与平台无关的中间格式，换一个来源只要产出一份同样结构的 JSON，插件代码不用动。见 [接入新平台](#接入新平台)。

## 安装

```bash
git clone https://github.com/ElioFanyu/dsh-workbench.git
```

然后在 DSH 里把它装成一个 bundle（插件管理面板选目录安装，或命令行）：

```bash
dsh plugin install-bundle /path/to/dsh-workbench
```

装完重启 DSH，输入框左侧会出现「工作台」按钮。

> 仓库**不含**抓取来的第三方提示词（版权原因）。只有自带内容时插件照常工作，见 [数据从哪来](#数据从哪来)。

## 它做什么

工作台不是 skill，而是一个**场景预设**：一段系统提示词 + 一组配套技能。这个插件复刻的正是这一层——

- 在输入框左侧加一个工作台按钮，点开是可搜索的工作台列表，也能展开看某个工作台挂了哪些技能、有哪些典型任务。
- 选中一个工作台，它的场景规则会注入**当前会话**的系统提示；再叠加一段技能路由小节，告诉模型这个工作台配套哪些技能、一个任务只挑一个主技能。
- 换会话就换一套规则：选择按 Session 存放，互不串台。取消选择即回到普通会话。

## 怎么用

1. 输入框左侧点「工作台」。
2. 搜索或直接点一个工作台，例如「Godot 游戏开发工作台」。**选中后面板会自动收起**，按钮上显示该工作台名。
3. 正常提问即可。此时模型已经在按该工作台的规则回答。
4. 想换一个：再点按钮打开面板，点别的工作台即可。
5. 想取消：打开面板，**再点一次当前选中的那个**（悬停提示「再点一下取消选择」），或者点底部的「取消当前工作台」。
6. 面板底部两个开关控制注入内容：「附带技能清单与路由规则」默认开，「附带典型任务示例」默认关。

## 数据从哪来

两个来源，分文件存放，互不覆盖。**仓库只带后者**：

| 文件 | 内容 | 是否入库 |
| --- | --- | --- |
| `data/custom-workbenches.json` | 本仓库维护的工作台（目前是 Godot 游戏开发） | ✅ 入库，MIT |
| `data/workbenches.json` | 从第三方 AI 产品抓取的场景提示词 | ❌ **不入库** |

抓取文件不入库的原因：里面是各家产品的场景提示词原文，版权归各自所有，公开分发不合适。

**这不影响使用。** 缺这个文件时插件照常工作，只是列表里少了那些抓取来的工作台——clone 下来跑起来就是这个状态。想要的话自己抓一份放进 `data/`，插件会自动合并，无需改代码。

### 自带内容：Godot 游戏开发工作台

| 项 | 内容 |
| --- | --- |
| 面板位置 | 列表第一位（自建的排在抓取的之前） |
| 技能 | 58 个，全部来自本机 `~/.dsh/skills`，按 8 组归类 |
| 环境事实 | Godot **4.7.2-stable**、`config_version=5`、可执行文件与 console 版路径、`D:/Workspace/Games/` 布局 |
| 注入长度 | 约 20.8 KB（含 58 条技能带摘要） |

八个技能组：立项与设计（6）、类型化玩法设计（13）、Godot 工程骨架（6）、Godot 玩法实现（13）、手感与体验（5）、美术资产（7）、构建测试与发布（4）、通用工程（4）。

提示词写的是**流程与纪律**，不是百科：先定核心循环再写代码、先灰盒后美术、一次一个可验证增量、每步都要真跑。同时把本机踩过的坑列成清单（`Node not found`、`previously freed instance`、`is_on_floor()` 恒假、场景单独运行就崩），以及产物必须落在项目子目录、临时文件要清理这类本机工作空间约定。

技能清单由 `data/build-custom-workbenches.py` 从真实 `SKILL.md` frontmatter 提取生成，摘要不是手写的——避免写得好看但和技能实际能力不符。

## 接入新平台

插件不认任何特定平台。工作台是一层中间格式，加一个新来源只需让它产出同样结构的 JSON。

一份工作台的完整结构：

```json
{
  "id": "平台-场景-唯一id",
  "name": "显示名",
  "version": "1",
  "custom": false,
  "intro": "一句话定位",
  "greeting": "开场白（可空）",
  "instruction": "场景系统提示词原文",
  "extraInstruction": "追加规则（可空）",
  "skills": [
    {
      "name": "技能 slug",
      "title": "中文/显示名",
      "summary": "一句话说明",
      "description": "完整说明（summary 为空时取首句）",
      "skillId": "原始 id（可空）",
      "skillType": "标识来源（可空）",
      "local": true
    }
  ],
  "plugins": [],
  "suggestions": [{ "text": "典型任务", "prompt": "点进去填的提示词" }],
  "creators": [],
  "skillGroups": [
    { "name": "分组名", "skills": [{ "slug": "技能 slug", "name": "…", "summary": "…" }] }
  ]
}
```

要点：

- **`local`**：技能是否真的装在本机。为 `false` 时面板标「未安装」，注入文本写「仅作能力说明」，不会假装能用。
- **`skillGroups`**（可选）：技能多时按组展示。不填就平铺成一条列表。
- **`custom: true`**：自建工作台。会排在抓取工作台前面，且不列出「其他可用工作台」长清单。
- **文件放哪**：抓取类数据放 `data/workbenches.json`（会被重抓覆盖），自建或长期维护的放 `data/custom-workbenches.json`。两个文件都读，按 id 去重，自建的优先。

接入步骤：产出 JSON → 放进 `data/` 并在 `package.json` 的 `files` 里登记 → 重启插件。**不需要改 `lib/` 里任何代码。**

## 边界

- 注入的是**来源平台的原始提示词**。其中提到的工作台转派（例如「教案转教师工作台」）在本插件里对应的是另一条可选工作台，不是外部服务。
- 工作台提示词里点名的技能，如果本地没装，模型只会看到能力说明；需要实际执行就到技能里安装对应包。
- 新开会话默认为「无工作台」。
- 来源平台改版后提示词会变，重抓一次对应数据文件即可，无需改代码。
- 自建工作台不列「其他可用工作台」长清单（20 个名字会分散注意力），只提一句「超出范围就建议切换」。

## 实现备注：面板「点一下就消失」的真实原因

原来的面板在渲染计数行时写成 `t('panel.count', String(n))`。宿主 locale 的签名是 `t(key, params对象)`，内部用 `name in params` 取占位符——传字符串会直接抛 `TypeError: Cannot use 'in' operator to search for '0' in 20`。

这个异常发生在面板渲染期间，被外层错误边界接住；边界当时 `return null`，React 于是卸载整棵子树，**按钮和面板一起消失**。所以现象是「点一下就没了」，而且再也点不回来。

修了三处：

1. 所有 `t()` 调用改传 params 对象（`fill(t, key, ...values)` 简写）。
2. 错误边界不再返回 `null`，改为渲染一个可点击的「工作台（点此重试）」按钮，并上报错误。
3. 打开状态提到模块级 `openStore`，按钮在 `pointerdown` 阶段处理并阻止冒泡——这两条是防御性的，防止 composer 重新注册 slot 时状态丢失。

## 排障通道

面板由浏览器渲染，出问题时浏览器侧没有可读日志。插件自带一条上报通道：

- `POST /dsh-workbench/trace` 追加一行到 `trace.log`
- `GET /dsh-workbench/trace-read` 读取最近 200 行

埋点覆盖挂载、卸载、点击、开关状态变化、渲染异常。遇到异常行为时，点一下按钮，然后读 `trace.log` 就能定位，不需要开浏览器。

验证方式：用 jsdom + 真实 React 跑回归，并使用**照抄宿主 `translate` 实现**的翻译器；10 项断言全过，分发出去的 bundle 也单独验证过。

## 关闭它

在「插件」里停用后，按钮消失、提示词不再注入，会话恢复普通行为。
